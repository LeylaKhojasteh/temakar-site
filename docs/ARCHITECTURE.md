# ARCHITECTURE.md — معماری و جریان درخواست

این سند برای خواندن سریع پروژه نوشته شده است: یک درخواست از نشانی تا قالب چه مسیری
را طی می‌کند، هر پوشه چه مسئولیتی دارد و چه چیزهایی عمداً ساخته نشده‌اند.

---

## ۱. نمای کلی

یک پروژهٔ جنگوی تک‌سرویس، بدون API و بدون فرانت جدا. صفحه‌ها با قالب‌های جنگو
رندر می‌شوند و تنها تعامل‌های پویا با مقدار کمی جاوااسکریپت و HTMX انجام می‌شوند.

```
مرورگر → gunicorn → config.wsgi → Settings(prod) → URLConf → Middleware → View → Template → HTML
```

## ۲. جریان یک درخواست

مثال: بازدید صفحهٔ یک خدمت در فارسی

1. **`config/wsgi.py`** نقطهٔ ورود سرویس است و `config.settings.prod` را بار می‌کند.
2. **`config/urls.py`** ادمین، فاویکون، `robots.txt` و `sitemap.xml` را جدا می‌کند و
   `i18n_patterns` را با `prefix_default_language=False` می‌آورد. نتیجه: انگلیسی در ریشه
   و فارسی با پیشوند `/fa`.
3. **`LocaleMiddleware`** زبان را از پیشوند مسیر تشخیص می‌دهد و فعال می‌کند.
4. **`AdminLanguageMiddleware`** برای مسیر `/admin/` زبان را فارسی می‌کند.
5. **`SecurityHeadersMiddleware`** هدرهای CSP، Permissions-Policy، CORP و HSTS را می‌گذارد.
6. **`apps.services.views.detail`** خدمت فعال را با نامک پیدا می‌کند؛ اگر غیرفعال باشد ۴۰۴
   می‌دهد.
7. **`apps.core.context_processors.site_context`** زبان، مسیر معادل زبان دیگر، `canonical`،
   تنظیمات سایت و فهرست خدمات (برای منوی کشویی هدر) را به همهٔ قالب‌ها می‌دهد.
8. **`templates/services/detail.html`** با `{% pick service "title" %}` فیلد زبان جاری را
   برمی‌دارد و متن غنی پاک‌سازی‌شده را نمایش می‌دهد.

## ۳. مسئولیت اپ‌ها

| اپ | مسئولیت | فایل‌های اصلی |
| --- | --- | --- |
| `apps/core` | صفحهٔ اصلی، ما کی هستیم، تنظیمات سایت، شبکه‌های اجتماعی، فاویکون، sitemap، خطاها، ترجمهٔ رابط، درج محتوا | `views.py`, `models.py`, `i18n.py`, `sitemap.py`, `context_processors.py`, `management/commands/` |
| `apps/services` | مدل خدمت، فهرست و صفحهٔ خدمت، لوگوی هر خدمت، محتوای شرکت | `models.py`, `views.py`, `admin.py`, `content.py` |
| `apps/contact` | فرم تماس، اعتبارسنجی، محدودیت نرخ، ذخیره و اطلاع‌رسانی | `forms.py`, `views.py`, `throttle.py`, `notify.py` |
| `config` | تنظیمات سه‌محیطی، مسیرها، میان‌افزار امنیتی | `settings/`, `urls.py`, `middleware.py` |

## ۴. مدل داده

```
Service            (چهار رکورد مستقل، بدون سطح دسته)
SiteSettings       (تک‌رکورد: تلفن، تلفن دوم، ایمیل، نشانی و ساعات کاری دوزبانه)
SocialLink         (اختیاری، برای فوتر)
ContactMessage     (پیام‌های فرم تماس)
```

| مدل | نکته‌های مهم |
| --- | --- |
| `Service` | نامک یکتای سراسری، عنوان و خلاصه و متن دوزبانه، تصویر اختیاری، `order`، `is_active`، متد `logo_template` |
| `SiteSettings` | همیشه یک رکورد (`pk=1`)؛ فیلدهای فارسی و انگلیسی جدا |
| `ContactMessage` | وضعیت `new/read/replied`، زبان فرم، `ip_hash` فقط برای محدودیت نرخ |
| `SocialLink` | برچسب دوزبانه، ترتیب، فعال |

متن غنی پیش از ذخیره با `apps/core/richtext.py` پاک می‌شود؛ قالب با `|safe` آن را
نمایش می‌دهد، چون ورودی از قبل محدود شده است.

## ۵. زبان

- `LANGUAGES = en, fa`، `LANGUAGE_CODE = en`.
- URL بخش‌ها در هر دو زبان یکسان است و فقط پیشوند تغییر می‌کند.
- متن‌های ثابت رابط در `apps/core/i18n.py` به‌صورت یک دیکشنری صریح نگه‌داری می‌شوند.
- محتوای واقعی در فیلدهای `_en` و `_fa` مدل‌ها است. اگر فیلد فارسی خالی باشد،
  `{% pick %}` به انگلیسی برمی‌گردد.
- هر صفحه `canonical` و جفت `hreflang` دارد؛ `sitemap.xml` هر دو زبان را با
  `xhtml:link` معرفی می‌کند.

## ۶. فرم تماس

1. `GET` فرم را با یک توکن امضاشدهٔ زمان‌دار (`TimestampSigner`) رندر می‌کند.
2. `POST` به ترتیب: تلهٔ ربات → محدودیت نرخ → اعتبارسنجی فیلدها → ذخیره → اطلاع‌رسانی.
3. خطاها با `role="alert"` و `aria-describedby` کنار فیلد نمایش داده می‌شوند و
   مقدارهای واردشده حفظ می‌شوند.
4. موفقیت بدون جاوااسکریپت با الگوی «ارسال، سپس تغییر مسیر» به `?sent=1` می‌رود تا
   رفرش، پیام را دوباره ثبت نکند.
5. با HTMX همان مسیر فقط قطعهٔ فرم را برمی‌گرداند (`HX-Request`).

ایمیل یک عارضهٔ جانبی است: اگر ارسال نشود، پیام در دیتابیس می‌ماند و خطا لاگ می‌شود.

## ۷. ناوبری خدمات

- صفحهٔ `/our-services/` چهار خدمت را با لوگوی دوبعدی متحرک هرکدام نشان می‌دهد.
- منوی هدر یک زیرمنوی کشویی دارد که همان چهار خدمت و «همهٔ خدمات» را فهرست می‌کند؛
  با کلیک، کلید Enter و Escape کار می‌کند و با کلیک بیرون بسته می‌شود.
- در منوی موبایل، همان چهار خدمت زیر آیتم «خدمات ما» آمده‌اند.
- صفحهٔ خدمت، متن کامل و دو خدمت مرتبط را نشان می‌دهد.

## ۸. امنیت

- CSP صفحه‌های عمومی بدون `inline`؛ پنل ادمین برای اجرای Quill و اسکریپت‌های جنگو
  استثنای محدود و مستند دارد.
- HTMX با `includeIndicatorStyles: false` تنظیم شده تا با CSP نسازد.
- فرم‌ها با CSRF؛ کوکی‌ها `HttpOnly` و در پروداکشن `Secure`.
- محدودیت نرخ و تلهٔ ربات سمت سرور اعمال می‌شوند، نه در کلاینت.
- آپلود تصویر: محدودیت حجم، نام فایل تولیدشده، اعتبارسنجی تصویر توسط Pillow.

## ۹. چه چیزهایی عمداً وجود ندارند

- API و Django REST Framework (مصرف‌کنندهٔ واقعی ندارد)
- حساب کاربری مشتری، سبد خرید، پرداخت
- پنل ادمین سفارشی (پنل جنگو کافی است)
- سطح دسته‌بندی خدمات (به درخواست مالک حذف شد)
- بلاگ، چت، نقشهٔ جاسازی‌شدهٔ سنگین (فقط iframe سبک)
- حالت تیره و کلید تغییر تم
