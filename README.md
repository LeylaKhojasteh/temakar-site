# تماکار | Temakar

وب‌سایت شرکتی تماکار: معرفی شرکت، چهار خدمت با متن کامل، صفحهٔ تماس با فرم پیام و پنل مدیریت جنگو.

- **زبان پیش‌فرض:** انگلیسی در ریشه (`/`)
- **زبان دوم:** فارسی زیر `/fa` با جهت راست‌به‌چپ
- **تمام متن‌ها و نام‌ها در دیتابیس قابل ویرایش‌اند** (به‌جز متن‌های ثابت صفحه‌ها که در قالب‌ها هستند)

---

## پیش‌نیازها

| ابزار | نسخه |
| --- | --- |
| Python | 3.11 یا بالاتر |
| Django | 5.2 |
| PostgreSQL | 14 یا بالاتر |
| Node.js | 20 یا بالاتر (فقط برای ساخت CSS) |

## راه‌اندازی محلی

```bash
# ۱. محیط مجازی
python -m venv .venv
.venv\Scripts\activate          # ویندوز
pip install -r requirements-dev.txt

# ۲. متغیرهای محیطی
copy .env.example .env          # ویندوز
# سپس DJANGO_SECRET_KEY را پر کن

# ۳. دیتابیس پستگرس محلی
#    یک کلاستر مستقل داخل .pgdata می‌سازد؛ به رمز ادمین پستگرس سیستم نیاز ندارد.
.\scripts\dev-db.ps1 init

# ۴. مایگریشن و درج محتوای شرکت
python manage.py migrate
python manage.py seed_content --with-images

# ۵. استایل‌ها
npm install
npm run css:build

# ۶. اجرا (دیتابیس و سرور با یک دستور)
.\scripts\dev.ps1
```

> اگر سیستم را خاموش و روشن کردی، فقط `.\scripts\dev.ps1` را اجرا کن؛ خودش کلاستر پستگرس را بالا می‌آورد و بعد سرور را.

سایت روی `http://127.0.0.1:8000/` و پنل مدیریت روی `http://127.0.0.1:8000/admin/` بالا می‌آید.

> **کلاستر محلی پستگرس:** روی پورت `5439`، با کاربر `temakar` و احراز هویت `trust` فقط برای `127.0.0.1`. دادهٔ آن در `.pgdata/` است و در مخزن ذخیره نمی‌شود. روزهای بعد با `.\scripts\dev-db.ps1 start` بالا می‌آید و با `.\scripts\dev-db.ps1 stop` خاموش می‌شود. این تنظیم فقط برای توسعه است؛ پروداکشن از پستگرس مدیریت‌شده با رمز استفاده می‌کند.

> **جایگزین:** برای آزمون سریع قالب‌ها بدون پستگرس، `USE_SQLITE=1` را در `.env` بگذار. تست‌ها به‌طور پیش‌فرض روی SQLite در حافظه اجرا می‌شوند و با `TEST_DB=postgres` روی پستگرس.

## دستورهای پروژه

| دستور | کار |
| --- | --- |
| `python manage.py runserver` | اجرای محلی |
| `npm run css:build` | ساخت CSS مینیفای‌شده |
| `npm run css:watch` | ساخت CSS در حالت تغییر زنده |
| `python manage.py migrate` | اعمال مایگریشن‌ها |
| `python manage.py seed_content --with-images` | درج محتوای واقعی شرکت (چهار خدمت) |
| `python manage.py check` | بررسی تنظیمات |
| `ruff check .` | لینت پایتون |
| `ruff format .` | قالب‌بندی کد |
| `pytest` | تست‌های واحد و مرورگری |

### تصاویر

- **عکس هر خدمت:** پنل → خدمات → خدمت → بخش «تصویر». پنل خودش تصویر را تا ۲۰۰۰ پیکسل
  کوچک می‌کند و نسخهٔ کارت و بندانگشتی می‌سازد.
- **سرصفحه‌ها و لوگو:** پنل → «تصاویر صفحه‌ها» (مدل `SiteImage`). پنج جایگاه: لوگو،
  نوار دربارهٔ ما، سرصفحهٔ معرفی، سرصفحهٔ خدمات، سرصفحهٔ تماس. تا وقتی تصویری ثبت نشود،
  قالب عکس موقت `static/img/demo/` را نشان می‌دهد.
- **وارد کردن دسته‌ای از یک پوشه:** نام فایل‌ها باید با نام جایگاه یا نامک خدمت یکی باشد.

```bash
python manage.py import_site_images "C:\path\to\photos"
python manage.py import_service_images "C:\path\to\photos"
```


معادل دستورهای استاندارد (build / lint / tsc / test) در این پروژه:

- **build:** `python manage.py check --deploy` با تنظیمات پروداکشن + `npm run css:build`
- **lint:** `ruff check .` و `ruff format --check .`
- **type check:** جنگو تایپ‌استاتیک ندارد؛ جای آن `python manage.py check` و تست‌ها
- **test:** `pytest` (واحد + Playwright)

## طراحی

- **جهت:** پوستر تخت با پنل‌های رنگی و نقشهٔ فنی؛ هر بخش یک رنگ زمینه دارد.
- **پالت:** سه سطح پایه و یک لهجه: کاغذ `#e8edf2`، کاغذ دوم `#dde4eb`، مرکب `#0c1a26`، سرمه‌ای `#10314a`، لهجهٔ آبی `#2f6289` و پلهٔ روشن `#a8c7de` برای متن روی زمینهٔ تیره. لهجه فقط در کنش‌ها و یک نوار پایانی به کار می‌رود.
- **تایپ:** Epilogue برای انگلیسی و Estedad برای فارسی؛ هر دو محلی.
- **هرو:** عکس ثابت پالایشگاه (`static/img/hero/poster.webp`) که بعد از بارگذاری، ویدیوی ابرها
  (`static/video/coastal-clouds.mp4`) روی آن پخش می‌شود — `muted`، `playsinline`، `loop` و
  بدون صدا. تا وقتی پخش واقعاً شروع نشده، همان عکس دیده می‌شود. با `prefers-reduced-motion`
  ویدیو اصلاً دانلود نمی‌شود.
- **لوگوی خدمات:** هر خدمت لوگوی دوبعدی متحرک خودش را دارد (دکل انتقال، توربین، خط نفت، شبکه).
- **منوی خدمات:** زیرمنوی کشویی در هدر با فهرست چهار خدمت.
- **صفحه‌های داخلی:** تصویر سرصفحه + پنل سرمه‌ای روی آن.

## ویرایش محتوا

همهٔ محتوای ساختاری از پنل `/admin/` انجام می‌شود:

- **خدمات:** نامک، عنوان و خلاصه در دو زبان، متن کامل با ویرایشگر متن غنی، تصویر، ترتیب و فعال
- **پیام‌های تماس:** فقط خواندنی؛ تغییر وضعیت با اکشن‌های «خوانده‌شده» و «پاسخ داده‌شده»
- **تنظیمات سایت:** تلفن، شمارهٔ دوم، ایمیل، نشانی، عبارت نقشه و لینک شبکه‌های اجتماعی

متن‌های ثابت صفحه‌ها (تیتر صفحهٔ اصلی، متن «ما کی هستیم» و مانند آن) در قالب‌های `templates/` هستند. پیش‌نویس همهٔ آن‌ها در `docs/COPY-DRAFT.md` آمده است.

> **وضعیت محتوا:** متن انگلیسی چهار خدمت و صفحهٔ معرفی از خود شرکت است. هنوز ترجمهٔ فارسی، لوگو و عکس واقعی نرسیده؛ عکس‌های فعلی جای‌نگهدارند و در `static/img/demo/SOURCES.md` مستند شده‌اند. با `python manage.py content_status` فهرست کمبودها را ببین. هیچ آمار، مشتری یا گواهینامه‌ای ساخته نشده است.

## امنیت

- نشست و کوکی امن، CSRF، HSTS و هدرهای امنیتی در `config/middleware.py` و `config/settings/prod.py`
- CSP سخت‌گیرانه برای صفحه‌های عمومی؛ پنل ادمین استثنای مستند دارد
- محدودیت نرخ فرم تماس بر پایهٔ شمارش در دیتابیس و هش IP (IP خام ذخیره نمی‌شود)
- تلهٔ ربات و سقف زمان پر کردن فرم
- متن غنی با `nh3` پاک‌سازی می‌شود؛ فقط تگ‌ها و ویژگی‌های مجاز می‌مانند

## استقرار

۱. یک سرویس وب و یک پستگرس مدیریت‌شده بساز (Render یا Railway).
۲. متغیرهای `.env.example` را در محیط پروداکشن تنظیم کن؛ `EMAIL_BACKEND` را به SMTP واقعی تغییر بده.
۳. دستورها:

```bash
pip install -r requirements.txt
npm run css:build        # CSS ساخته‌شده از assets/css/main.css
python manage.py collectstatic --noinput
python manage.py migrate
gunicorn config.wsgi:application
```

۴. متغیر `DJANGO_SETTINGS_MODULE=config.settings.prod` و `SITE_URL` و `DJANGO_ALLOWED_HOSTS` را تنظیم کن.
